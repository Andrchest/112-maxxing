#### Преподаватель (этапы E31, E32, E33)

**Q-E9b-2. Что считать «заполнением карточки» у ДДС для норматива 3 минуты?**
- Варианты:
  - (а) первый статус по каждой службе (Принята/Не принята);
  - (б) статус «Выехала/Начало реагирования» по основной службе;
  - (в) не измерять 3 минуты в режиме ДДС, только 30 с на принятие.
- Источники: заказчик (REQ-6020): «30 секунд… открыть, и в течение трёх минут её заполнить».
  Памятка определяет только 30 с на подтверждение (с. 5, с. 21). ДДС карточку не заполняет, а
  ставит статусы.
- **Ответ (2026-09-26):** вариант (а) — первый статус по каждой службе (Принята/Не принята).
  Сделано: I5 E36.

**Q-E9b-3. Как определять «сдал / не сдал»?**
- Варианты:
  - (а) доля баллов не ниже порога (например, 70 %);
  - (б) не больше N проваленных правил;
  - (в) любая критическая ошибка означает «не сдал»;
  - (г) сочетание.
- Также нужны значения по умолчанию, и нужно решить, задаётся ли порог на занятие или на сценарий.
- Источник: ТЗ ¶241 «пороги допустимых ошибок, требования к синтаксису ответов». Шкала нигде не
  задана.
- **Ответ (2026-09-26):** вариант (г) — сочетание (порог баллов + лимит проваленных правил +
  критические ошибки). Режим должен быть настраиваемым: только порог, только правила и т. д.
  Значения по умолчанию и уровень порога (занятие/сценарий) определяет этап.
  Сделано: I5 E38.

**Q-E9b-4. Изолировать ли преподавателей друг от друга?**
- Варианты:
  - (а) преподаватель видит всё, но менять может только своё: запуск, прерывание, пересчёт,
    публикацию, комментарии, группы;
  - (б) видит и меняет только своё;
  - (в) как сейчас: всё общее.
- Источники:
  - ТЗ ¶245 запрещает «вмешательство в работу других преподавателей»;
  - на Q&A (L786–789) сказано, что преподаватель «видит действия… всех обучаемых»;
  - в I3 (E9a) решено, что группы общие для всех преподавателей.
- Безопаснее вариант (а): он выполняет оба источника. До ответа ничего не меняется.
- **Ответ (2026-09-26):** вариант (а) — преподаватель видит всё, но менять может только своё.
  Сделано: I5 E39.

**Q-E9b-5. Экспертная оценка преподавателя: какая?**
- Варианты:
  - (а) отдельная итоговая оценка рядом с автоматической: баллы той же шкалы или 5-балльная;

  приоритетен» (REQ-6024). В любом варианте изменение пишется в журнал аудита (¶246).
- **Ответ (2026-09-26):** вариант (в) — только подтверждение «проверено» (существующий статус

#### Шифрование SIP (этап I7 E44)

**Q-I7-E44-1. Выключать ли обычный (нешифрованный) SIP?** По ответу на Q-E15-2 шлюз теперь
принимает SIP поверх TLS на порту 5061, и звонок по TLS идёт только с шифрованием голоса (SRTP).
Обычный SIP на 5060 (udp/tcp, голос без шифрования) оставлен рядом, потому что не все настоящие
аппараты и софтфоны умеют TLS/SRTP. ТЗ ¶293 требует шифровать «все передаваемые данные».
- Варианты:
  - (а) оставить оба: TLS для тех, кто умеет, обычный SIP для остальных (сейчас так);
  - (б) только TLS + SRTP: `SIM_SIP_TRANSPORTS=tls` — телефон без TLS/SRTP не подключится;
  - (в) обычный SIP только для отдельных аппаратов (список адресов или логинов) — это новая
    настройка, её пока нет.
- Сейчас: (а), по умолчанию `SIM_SIP_TRANSPORTS=tls,udp,tcp`; переключение на (б) — одна
  строка в `.env`, без изменения кода (`docs/RUNBOOK.md`, «Шифрование SIP»).

#### Нагрузка (этап I7 E48)

**Q-I7-E48-1. Сколько обучаемых одновременно должен выдерживать один сервер?** Мы замерили

(проверено).

  - (б) довести до 100 обучаемых. Это отдельная работа:
    - запуск нескольких процессов сервера (не проверялся);
    - пересчитывать состояние сессии частями, а не целиком на каждом шаге;
    - уменьшить ответы, которые отдаются чаще всего;
    - запускать карточки занятия не одним запросом.
