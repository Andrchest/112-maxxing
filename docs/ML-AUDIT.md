# Атомарный ML-аудит 112

## Алгоритм

Для каждого атомарного вопроса модель выбирает **ровно один токен: `да` или `нет`**.
Третьего семантического ответа, свободного объяснения, сгенерированной цитаты или
модельного назначения весов нет.

Веса берутся из JSON-регламента и **не передаются модели**. Код считает:

```
вклад_i = вес_i × (1, если токен «да», иначе 0)
балл = 100 × Σ вклад_i / Σ вес_i
```

Та же формула используется для каждой категории. API возвращает токен,
`awarded_weight`, исходный вес, общий/покатегорийный итог и контрольные суммы.
Это HealthBench-подобная взвешенная проверка критериев, а не использование датасета
HealthBench или заявление об эквивалентной клинической валидации.

Таймаут, несовместимый токенизатор, отсутствующий исходный лог или другая техническая
ошибка — `passed=null` с `issue`, **не третий ответ модели** и не автоматический «нет».
В этом случае итог недоступен; `coverage_percent` показывает техническое покрытие.

## Два явно различимых адаптера

### Полный attention-адаптер

```dotenv
SIM_ML_AUDIT_PROVIDER=attention
SIM_ML_AUDIT_ATTENTION_MODEL_PATH=/models/local-hf-checkpoint
SIM_ML_AUDIT_ATTENTION_MAX_TOKENS=2048
SIM_ML_AUDIT_TIMEOUT_MS=20000
```

`backend/app/inference/llm/attention_auditor.py`:

- Локальный HF causal LM, fast tokenizer с offsets, eager attention. Только локальные
  safetensors, `trust_remote_code=False`; автоматической загрузки из сети нет.
- `да` и `нет` должны кодироваться двумя различными одиночными токенами. Остальным
  логитам принудительно присваивается `-inf`; выбирается один из этих двух токенов.
- На строке решения 4-D causal attention mask допускает только позиции текста
  оператора/карточки и контекста заявителя. Контекст не допускается как цитата.
- Усредняются головы последних двух attention-слоёв; максимум выбирается только среди
  токенов источника оператора. Окно ±6 токенов обрезается границами этого источника,
  переводится в символьные offsets и вырезается из оригинала.
- Цитата **никогда не генерируется**. UI подсвечивает `[start,end)` в исходном тексте;
  индексы — Unicode code points, не UTF-16.

Нужны optional `torch`/`transformers`/fast tokenizer (в workspace они уже доступны через
существующий extra `asr-gigaam`). GGUF llama.cpp — не HF safetensors checkpoint.
Проверенный архитектурный smoke использует настоящий tiny Llama forward без обученных
весов. Другие архитектуры должны поддерживать additive 4-D mask и `output_attentions`;
несовместимость даёт техническую ошибку, а не скрытый переход на генерацию цитат.

CPU-forward выполняется вне event loop. При таймауте запрос завершается, но уже начатый
CPU-forward нельзя безопасно оборвать: single-flight gate удерживается до его окончания,
чтобы повторные запросы не загружали параллельно новые копии модели.

### Совместимый HTTP-режим без attention

```dotenv
SIM_ML_AUDIT_PROVIDER=llm
SIM_EXPLANATION_LLM_PROVIDER=llama_cpp
SIM_EXPLANATION_LLM_BASE_URL=http://127.0.0.1:8080/v1
SIM_EXPLANATION_LLM_MODEL_NAME=Qwen3-4B
```

Тоже только `да`/`нет`: llama.cpp grammar `root ::= "да" | "нет"`, `max_tokens=1`,
`temperature=0`, thinking отключён. Проверяются фактический ответ и число выходных токенов.
JSON, объяснения, «не уверен» и многотокенные ответы отклоняются как нарушение протокола.
Этот режим возвращает `evidence_method=binary_token` и **не выдаёт никаких цитат**:
HTTP-порт не предоставляет attention-тензоры. UI явно указывает ограничение.
`fake` не притворяется реальной оценкой.

В Compose URL должен указывать на внутренний `http://llama-server:8080/v1`.

## Регламенты и контекст

`backend/app/config/ml_audit_rubrics.json`: общий чек-лист, шаблоны `fire`, `traffic`,
`gas`; существующая виньетка «Пожар в квартире» связана с `fire` по UUID версии.
`scenarios[UUID]` принимает имя шаблона или полный объект `{version, criteria}`.
`SIM_ML_AUDIT_RUBRICS_PATH` позволяет использовать внешний JSON (в Docker нужен mount).
Изменение вопросов/весов не требует Python-кода. Регламенты учебные, не ведомственно
утверждённые. Для новых версий ДТП/газа нужно явно добавить UUID-привязку.

`dialogue` проверяет финальные реплики 112-оператора, `card` — видимые поля карточки
и получателей из неизменяемого снимка передачи. Реплики ДДС не засчитываются оператору.
Карточки, сгенерированные для DDS-only сценария, не оцениваются как работа 112-стажёра.
Слова заявителя — только контекст. Скрытый WorldTruth не передаётся модели.
Синонимы/ошибки ASR интерпретируются моделью; исходный текст не исправляется.

## Автоматический запуск и хранение

Сначала применить миграцию **`0022_ml_audit`** обычным `make migrate`.
`SIM_ML_AUDIT_AUTO_ENABLED=true`: при настроенном реальном провайдере lifespan запускает
воркер. Он обнаруживает завершённые сессии 112 после 10-секундного grace interval,
проверяет очередь каждые 5 секунд, берёт DB-lease на 5 минут. Перезапуск не теряет
задания; `SKIP LOCKED` и lease-token защищают от конкурирующих/устаревших воркеров.
Технический сбой повторяется через 60 секунд, максимум три автоматические попытки.
Симуляция, официальный балл, события и pass/fail не меняются.

`ml_audit_runs` хранит отдельную запись каждого запуска: UUID, время, модель, регламент,
хеш видимого входа, решение и evidence. Повторная оценка не перезаписывает предыдущую.
`ml_audit_jobs` хранит попытки и аренды. При удалении сессии эти данные удаляются каскадно.

- `GET /api/v1/reports/{id}/ml-audit` — сохранённый результат либо `null`.
- `POST /api/v1/reports/{id}/ml-audit` — оценить; полный совместимый результат используется
  из кеша. `?regenerate=true` создаёт новый запуск.
- Права, принадлежность и публикация отчёта проверяются **до чтения кеша**. Ключ кеша
  включает точный видимый вход, регламент и конфигурацию адаптера. Результат инструктора
  с более широкими данными не выдаётся DDS-стажёру.

Страница отчёта загружает сохранённую оценку после обновления и опрашивает автоматический
результат; ручная кнопка пересчитывает. История хранится в БД, отдельного экрана истории
и включения в PDF/Excel пока нет.

## Smoke-проверки

```
uv run pytest backend/tests/api/reports/test_ml_audit.py backend/tests/api/test_lifespan.py -q
uv run pytest backend/tests/unit/application/reports/test_ml_audit.py backend/tests/unit/application/reports/test_ml_audit_route.py backend/tests/unit/inference/llm/test_attention_auditor.py -q
cd frontend && npm run typecheck && npx vitest run src/features/report
```

API-тесты используют существующие тестовые PostgreSQL/Redis и отдельную временную БД;
проверяют миграцию, HTTP, права, сохранение, неизменность официального балла, автоматический
запуск, retries и lease. Tensor-smoke без torch/transformers пропускается.

Опциональный smoke настоящей модели, только синтетический текст:

```
SIM_ML_AUDIT_SMOKE_URL=http://127.0.0.1:18189/v1 uv run pytest backend/tests/test_ml_audit_live.py -q
```

Attention — атрибуция, не доказательство семантической правильности: предыдущие hidden
states уже содержат контекст, а пик может быть нерелевантен критерию. Форсирование токенов
и точность цитат не устраняют ошибки решения модели. Перед использованием оценок для
аттестации нужны экспертный корпус и измерение качества на выбранном checkpoint.
