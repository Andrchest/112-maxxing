# Контур требований

Здесь ведётся независимый, проверяемый реестр требований проекта. Оригиналы не
редактируются; выводы и нормализованные формулировки хранятся отдельно.

## Структура

- `sources/` — полученные исходные документы в неизменном виде.
- `normalized/` — обработанные версии: выделенные, дедуплицированные и
  однозначно сформулированные требования.
- `traceability/` — матрицы трассировки «требование → код → тест → доказательство».
- `assessments/` — результаты проверки по документам, коду и тестам.
- `evidence/` — ссылки, журналы и другие проверочные артефакты.
- `INDEX.md` — единый индекс документов и требований со статусами.

## Правило работы

1. Новый документ кладётся в `sources/` без изменения имени и содержания.
2. Каждому извлечённому требованию присваивается стабильный ID вида `REQ-0001`.
3. Нормализованная формулировка не заменяет оригинал: она всегда содержит
   ссылку на файл и раздел источника.
4. Статус меняется только при наличии зафиксированного основания в поле
   «Доказательство» индекса или матрицы трассировки.

## Допустимые статусы

| Статус | Значение |
|---|---|
| `не обработано` | Документ или требование ещё не разобрано. Это начальный статус. |
| `соблюдено` | Требование однозначно реализовано и подтверждено достаточными доказательствами. |
| `частично` | Реализация или доказательства покрывают только часть требования. |
| `не соблюдено` | Требование отсутствует, ему противоречит реализация либо есть воспроизводимое нарушение. |

Не следует использовать «соблюдено» только на основании комментария в коде,
плана или самооценки проекта: нужны код, тест, результат прогона либо иное
проверяемое доказательство.
