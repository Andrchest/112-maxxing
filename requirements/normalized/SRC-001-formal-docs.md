### How the documents were read
- ТЗ: `uv run --with python-docx` script iterating the document body in order (paragraphs and table
  cells), recording paragraph style and Word list membership (`numPr` num id / level); the docx
  was also unzipped to check headers (empty), comments/footnotes (none), text boxes/drawings (none)
  and the one content control (the table of contents, whose page numbers are used below as
  «TOC p.N»). Every paragraph was either itemised or is a list lead-in/sub-heading whose text is
  carried inside the items' `Source` (the generator printed the non-itemised paragraphs; all are
  lead-ins such as «Сервис должен обеспечивать:» or the criteria group titles).
- PDFs: `pdftotext` (raw and `-layout`), `pdffonts`, `pdfimages -list`, and every page rendered with
  `pdftoppm` and viewed. All three PDFs have a complete text layer (the answers PDF uses Type-3
  fonts but its text layer is intact and matches the rendered page). Page 1 of the participant
  instruction is a single raster image (cover) and was read visually. PDF quotes were checked
  mechanically against the text layer (whitespace-insensitive); datasheet list items that wrap
  across its two-column layout were checked against the `-layout` output and the rendered page.
- Chat context (message ids/dates/authors) was taken from `messages.html` with a Python parser only
  to establish provenance and speakers; chat statements themselves are X1 scope (REQ-1xxx) and are
  cited here by message id only where they bear on these documents.

### Citation conventions
- ТЗ clauses are **not numbered** in the source (they are unnumbered «●» bullets under a lead-in
  sentence; only the submission list is a Word numbered list and the criteria groups carry typed
  numbers «1.»–«5.»). `Source` therefore gives: heading › sub-heading, the page of that heading from
  the document's own table of contents («TOC p.N»), the lead-in sentence, the bullet's ordinal
  position under that lead-in («item N», counted by this extraction; «item 3.1» = first
  second-level bullet under item 3), and «[¶N]» = ordinal of the paragraph in the document body as
  enumerated by python-docx (reproducible, not printed in the source).
- Where one source sentence contains several checkable statements it is split, and `Verbatim`
  holds the exact fragment.
- Datasheet list sections are quoted as `;`-joined bullet texts in source order.

### 3.1 Contradictions inside the ТЗ (all in one document, dated 01.09.2026 by file name)
1. **Incoming-call channel.** REQ-2100 allows «через виртуальную IP-телефонию или
   текстовые сообщения»; REQ-2044, REQ-2118 and REQ-2249 state IP telephony / VoIP
   (local SIP server) without an alternative; REQ-2139 sets VoIP latency ≤ 150 ms. See REQ-2432.

   поддержка работы с мобильных устройств» under «Рекомендуется реализовать» (optional);
   REQ-2157 («Адаптивность под различные устройства») and REQ-2342 («как в
   десктопной, так и в мобильной версии») state it as required. See REQ-2433.

   системы-112») and REQ-2127 vs REQ-2082/REQ-2104 (no external networks),
   REQ-2106 (imitation only) and REQ-2136 (internal API «без взаимодействия с внешними
   системами»); the criteria REQ-2349/REQ-2359 score «Возможность интеграции в любые
   другие системы». See REQ-2434.
4. **Criteria refer to functions the requirements do not define.** REQ-2351, REQ-2352,
   REQ-2361, REQ-2363, REQ-2369 (forecasts, calculations, infrastructure
   behaviour) have no counterpart among the ТЗ requirement sections. See REQ-2435.
5. **Trainee role wording.** Title/REQ-2005 (ДДС operator) vs scenario 2 REQ-2268/REQ-2269
   (imitated caller + filling cards in an АРМ-112 interface imitation). See REQ-2436.
6. **Verbatim repeats with identical values (no conflict):** backup ≥ 1/day REQ-2126 = REQ-2235;
   vertical/horizontal scaling REQ-2144/REQ-2145 = REQ-2250/REQ-2251;
   RBAC REQ-2124 = REQ-2242; multi-level auth REQ-2123 = REQ-2240; data protection

   remote control REQ-2087 = REQ-2116; scenario-3 report REQ-2289 = scenario-2 report REQ-2271–REQ-2276.
